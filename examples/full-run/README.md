# examples/full-run/ — 迷你全链样例工作区

> **这是什么**：一条完整跑通的七阶段产物链（迷你规格，各文件 30-50 行），让新用户 5 分钟看懂"跑完一轮产出什么、每个门拦了什么"。
> **数据来源**：02/03/04 双版本来自 `../../tests/fixtures/mini-good/` 回归夹具（D7 同源组装）；00/01/05/06/07/08 为同数据构造的迷你样例——**全部是样例数据，不是真实作品**。
> **目录隔离提示**：真实写作产物应落盘到技能目录之外的项目目录；本目录只是包内演示。

## 怎么用这个样例

1. **顺着读**：00 → 01 → 02 → 03 → 04 → 05 → 06 → 07/08，就是一次完整执行的产物顺序；
2. **对着门看**：每个文件末尾的"门禁自检"行 = 该阶段的验收 checklist，真实写作时逐项对照；
3. **跑机检**（需 python3 ≥3.8，零依赖）：

   ```bash
   python3 ../../scripts/check-artifacts.py "examples/full-run"     # 产物链字段对账（A-M 项，含 N-Q 细纲六表对账）
   python3 ../../scripts/check-fingerprint.py "examples/full-run/08-结构指纹.md"  # 指纹机检
   python3 ../../scripts/check-process.py "examples/full-run"       # 终审工序留痕核验
   ```

   预期：全部 exit 0（样例按可过口径构造；⚠️ 级条件项已在 05 报告中如实标注原因）。

## 样例与真实执行的差异（提醒）

- 样例正文是**缩略正本**（fixtures 迷你稿），真实产物是 12000-16000 字全稿（AT-01）；
- 样例的机检分值是为演示填写的结构数据，真实报告必须引用 `check-mss.py` 实测输出（标称即实测）；
- 样例的平台/相似度条件项标注"未核/未测+原因"，真实执行时联网可核才核、有工具才测。
