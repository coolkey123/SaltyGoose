# 会话拆分与断点续写（session-split.md）

> 长流程七阶段 + 四确认门，单会话塞不下，也不该塞。**产物文件链是唯一可靠的外置记忆**——对话会忘，文件不会。
> 拆分点 = 确认门；每段启动只带"本段输入产物 + 当前阶段规则"。

## 一、会话拆分五段表

| 会话段 | 覆盖阶段 | 启动输入 | 收口动作（断点条件） |
|---|---|---|---|
| 第 1 段 | 1-2 | 用户想法/素材/采集卡；references：principles + stage1 + genre-map | `00-选题评估.md`/`01-梗概.md` 落盘且过门；**用户拍板梗概（确认门②）** |
| 第 2 段 | 3 | `01` 产物；references：stage3 + fingerprint + deliverables（02 模板） | `02-细纲.md` 落盘且两段门过；**用户确认细纲（确认门③，最佳断点）** |
| 第 3 段 | 4 | `02` 上篇 + 六表；references：stage4 + style-rules | `03-正文.md` 各批次落盘过单章门（每批 2-3 章，批间可断）；全篇核验 7 项过 |
| 第 4 段 | 5-6 | `03` 净稿 + 六表；references：stage5 + kill-ai + stage6 + mss-rules | `04` 双版本 + `05-初审报告.md` + `05-终审报告.md` 落盘；阶段 6（初审与终审）**优先隔离 sub-agent 审稿**（材料包六件）；初审报告 + 终审报告双报告，终审七工序全过且工序留痕核（check-process）通过 |
| 第 5 段 | 7+收尾 | `04`/`05`；references：stage7 + deliverables（06/07/08 模板） | `06-投稿包/`/`07-复盘.md` 落盘；**用户点头交付（确认门④）**；指纹实落回填 |

**为什么第 2 段是最佳断点**：细纲确认后，全部创作决策已固化成文件（结构/付费点/六表/人设/伏笔），写作段零历史包袱——断了任何一段，损失都小于细纲前断。

## 二、何时该断（四信号，命中任一即收口当前会话）

1. **到达确认门**（①②③④之一）——等用户拍板即天然断点；
2. **单会话段已覆盖 ≥2 个阶段**（会话拆分表的段边界）；
3. **当前阶段产物已落盘且质量门/脚本自检通过**（产物链已可作下段输入）；
4. **上下文吃紧**（长产物粘贴/多轮长输出后，恢复成本低于继续压塞）。

## 三、新会话重进五步

1. **读 SKILL.md 定位当前阶段**——产物链缺号即断点在缺号处；
2. **只加载当前阶段规则**（卡一索引见 `../README.md` 第四节），禁全量加载 references；
3. **读项目目录上一阶段产物作输入**（不读全部历史产物，不依赖对话记忆）；
4. **核对产物链完整**（00-08 无跳号、与六表台账一致）；
5. **从中断处的质量门或确认门继续**；产物链有缺口按根因路由回补，禁跳阶段硬续。

## 四、长稿按批落盘（第 3 段专用）

- 每批 2-3 章，批末跑单章门 + 三件套（`--fragment` 口径）；
- 批间可断：断点记入当批末尾一行"【续写锚点】下章钩位/钩型/伏笔待办"；
- 禁单次输出超过 3 章（输出过载 = 质量滑坡 + 上下文膨胀双杀）。

## 五、方式①全自动的降级自检规则

连跑七阶段时会话拆分不消失，只是断点不停留：

1. 每阶段产物照常落盘、质量门照常执行、编造防线照常生效；
2. 确认门降级为快照自检点（一行摘要，格式见 `../../assets/prompts.md` 第三节）；
3. 单会话段仍按五段表收口——**方式①只省"等拍板"的停留，不省上下文管理**；段边界到点即断，下段按重进五步续；
4. 用户随时可叫停或对任一阶段发修改意见——叫停即回到方式②逐阶段确认。
