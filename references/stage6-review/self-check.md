# 阶段 6 · 初审与终审 — self-check（该怎么自己检查）

> **本文件回答：该怎么自己检查。** 该干什么/怎么做见同目录 `workflow.md`；验收线见 `quality-gate.md`；禁令见 `rules.md`。
> 脚本调用口径（命令模板/退出码/⚠️ 人工确认流程）以 `../../scripts/README.md` 为唯一权威，本文件不复述。

## 一、执行顺序自检（顺序错了结论就错）

| 步 | 动作 | 自检点 |
|---|---|---|
| 1 | 确认审稿隔离方式（①独立 sub-agent / ②隔会话 / ③隔 30 分钟+标注） | 走③时，18 维门值收紧到 ≥8.8，且报告首行标注"⚠️ 同上下文自审" |
| 2 | 跑 `check-artifacts.py <项目目录>` | ❌字段空缺先回补再进评分；⚠️对账差异随报告附上 |
| 3 | 跑 `check-mss.py`（机检数字报告） | 标题/导语/梗概/金句显式传入；伏笔回收 CSV 五列在位 |
| 4 | 主观六维逐维打分 | 每维有依据（引 AT 号），禁裸分 |
| 5 | Findings Schema（S1-S4）问题清单 | 每条有证据位；红队条目三档（真实缺陷/主动承担/建议）不混写 |
| 6 | 逻辑验证八查 | 因果链/信息差三层/规则边界/时间数字台账/行为合理性/反转公平/伏笔出处/人设事实 |
| 7 | 75 项勾选表逐项过 | 每项 ✅/❌/⚠️ 实判，⚠️ 附原因与处置；禁只写"全过" |
| 8 | 6b 终审七工序按序过 | 工序号连续登记进「终审工序执行记录」表（原九工序的平台口径核验/相似度检测两项 已删，工序重排为七道） |
| 9 | 跑 `check-process.py <项目目录>` | 工序表编号连续 / 结论项数与裁决表行数一致 / MSS 分值可追溯到机检节 |

## 二、常见自查失败的定向修法

| 自查不过项 | 定向修法 |
|---|---|
| check-mss 分值与报告手抄数不一致 | 改稿后必须重跑机检并更新报告——手抄数字与稿件脱节是 check-process 头号目标 |
| 18 维均分够但单项 <6 | 门不过——双条件取严（均分 ≥8.00 且无单项 <6） |
| 折算维好看但 MSS 触硬门 | 自我矛盾——对应折算维压回 ≤5（硬门联动纪律）；且硬门稿**禁入 18 维评分**：12 硬门全触发时其余 13 维满分仍能算出 8.61 过门分（算术实证），故 P0 一票否决先于 6b，本表作废回 6a |
| 6a 均分压线 7.0 以为稳过 6b | 换算关系：第 1-6 维直接取 6a 分，6a=7.0 时后 12 维须均分 8.5 才够 8.00——终审比初评严是设计使然，打 6a 前先算这笔账 |
| 盲测只做了内部对照 | 结论禁写"具备爆款相"；四维标"⚠️ 未与外部真作品对照"，只写内部对照胜面 |
| 盲测连内部对照源都没有 | 第 15-18 维记「⚠️ 未测」不计分，均分按已计分维折算，禁出「可用」档——只能「需补信息（盲测对照源）」 |
| 红队写"未找到拒点" | 重写——必须列至少 3 条最想拒的点 |
| 待核项没做（投稿面平台规则等） | 填"⚠️ + 原因"，禁留空、禁假合格（R12 通用纪律——初审/终审不再设平台口径/相似度工序） |
| 回退超过 2 轮 | 停下汇报卡点交用户裁决，禁无上限震荡（AT-51） |
| 算术指控被作者驳回 | 先复算自己的单位换算与算式——算不出来不许断言"作者算错"（审稿人纪律①） |

## 三、报告产出自查（交出去前的最后一遍）

1. 固定四节在位：结论 / 最致命 3 问题 / Findings 全单 / 最小改动修改方案；
2. 机检数字报告作为第一节附件；
3. 终审工序执行记录表随报告附（七道工序逐条留痕，删两项后重排）；
4. 18 维评分表 + 75 项勾选表齐全，评分每维可追溯、勾选每项有实判；
5. 条件项状态（已核/已测/⚠️ 未核+原因）显式可见。
