# 阶段 6 · 初审与终审 — workflow（该干什么 + 该怎么做）

> **本文件回答：该干什么、该怎么做。** 验收线（六维门/18 维评分表/75 项勾选表）见同目录 `quality-gate.md`；执行检查口径见 `self-check.md`；禁令见 `rules.md`。
> Reference Gate：进入阶段 6 前必读。数值口径以 `../shared/authority-table.md` 为准（AT-22/54/61/62/63/64/65/66/67）。
> 参照：`../shared/mss-rules.md`（MSS 五模块/12 硬门/输出纪律）、`../README.md` 三级拒稿门总览。

## 一、做什么

审稿只出**问题清单与评分**，不直接改稿——把"发现问题"和"修改"分开。顺序：**先机检数字报告，后主观六维评分**，按根因路由回退。

**初审（6a）/ 终审（6b）两半（隔离审稿两轮制）**：**初审（6a）**= 机检数字报告 + 主观六维评分 + 根因路由，产出 `05-初审报告.md`；**终审（6b）= 终审放行**（跨章扫描 → 跳读测试 → 付费测试 → 盲测对比 → 18 维终审 ≥8.00 → 红队终审 → 工序留痕核），产出 `05-终审报告.md`。**初审与终审各出一份报告**（双报告制：初审报告是问题清单与评分载体，终审报告是放行结论与工序留痕载体，合起来才构成"可发"证据链）。「初审均分 ≥7 无 S1/S2 + 终审 18 维达标」两者同时满足才可发（AT-61/62）。

**冷启动纪律（优先级最高）**：审稿必须与写作过程隔离——采信门值与三档降级见 `quality-gate.md` 第一节同文段（与 SKILL.md 双锁）；隔离审稿的派发方式与材料包六件见 `../../AGENTS.md` §1.1/§1.2。

**审稿人纪律（必守三条）**：①**算术指控必须先复算**——指出正文数字/量级错误前，自己把单位换算与算式写一遍，算不出来的不许断言"作者算错"（实战教训：审稿人误判"十万口×半升≠一日五百石"量级错误，实为一石=十斗=一百升、原文正确）；②**发现问题与改稿分离**——审稿人不下场改，改由根因路由回对应阶段；③**"设计取舍"不得包装成"已解决"**——红队条目须逐条标真实缺陷/主动承担/建议，三档不得混写。

## 二、机检数字报告（check-mss.py，先于主观评分）

### 2.1 调用方式

```bash
python3 scripts/check-mss.py --text 项目-{书名}/机检提交/正文纯文本.md --title "标题" --intro "导语" \
  --logline "一句话梗概" --quotes "金句1；金句2；金句3" \
  --foreshadow 伏笔回收.csv [--paywall "锚句"] [--person auto|1st|3rd] [--json]
```

输入纪律：标题/导语/梗概/金句**显式传入**（禁让脚本从正文猜——猜错=整份报告偏）；伏笔回收 CSV 五列（埋设位置/埋设原句/回收位置/回收原句/回收方式）。**送检正文面派生自净稿**（stage5 R11）：首选 `机检提交/正文纯文本.md`（净稿 + 插回 `[[首锁]]`/`[[二锁]]` 标记，模板见 `../../templates/machine-check-package.md`）；未备机检包时用 `04-正文净稿.md` + `--paywall` 锚句等效卡点位——**禁直引 `03-正文.md`**（写作期稿未过净稿冻结流程，直引它 = 机检面与投稿面不是同一份文本，修）。

### 2.2 MSS 五模块（AT-66）

| 模块 | 权重 | 子项 |
|---|---|---|
| **F 形式** | 30 | F1 总字数 12000-16000（10）+ F2 分节合规（8）+ F3 段落 ≤50 字占比 ≥60%（6）+ F4 平均句长 ≤25（3）+ F5 「」对话（3）；扣分项：前 500 字"我"<5 扣 2、半角标点 >10% 扣 2、三称稿一称扣分 |
| **B 标题导语梗概金句** | 20 | B1 标题长度三档（6）+ B2 标题无问号感叹号（4）+ B3 标题冲突词共现（0 分纯报告）+ B4 导语 80-150（4）+ B5 导语首句冲突（2）+ B6 一句话梗概 ≤50 含冲突悬念词（2）+ B7 金句 3-5 句×≤40 字（2） |
| **T 结构位置** | 25 | T1 开篇 100 字冲突标记共现 ≥2 类（5）+ T2 前 300 字钩子/困境（4）+ T3 首锁字位 3000-4000 或占比 25-35%（5）+ T4 卡点前 200 字情绪词（3）+ T5 卡点后 300 字钩子 ≥3 处不同类型（4）+ T6 章末动作钩（2）+ 章末新问题（2） |
| **D 密度代理** | 15 | D1 情绪词密度 0.8-1.2/千字（4，AT-35 机检代理——人工拐点核以此条为准）+ D2 推进/反转词 ≥1/300 字窗（3）+ D3 打脸词 ≥0.5/600 字窗（3）+ D4 新名词 ≥2/2000 字窗（3）+ D5 钩子类型轮换率 ≥60%（2） |
| **R 回收兑现** | 10 | R1 伏笔回收率 ≥80%（6）+ R2 标题/导语核心词前 3000 字兑现（4） |

**分档**：**≥80 高匹配 ‖ 60-79 低匹配 ‖ <60 不匹配**。**12 项硬门任一触发 → MSS 封顶 59**（12 硬门=总字数/标题>20 字/标题问号感叹号/导语缺失或离带/段落合规率<60%/对话未用「」/混用第x章或编号异常或分节数<3/首锁缺失或偏离/伏笔回收表缺失或回收率<80%/开头 100 字无共现/连续两章章末无动作钩/核心词前 3000 字未出现）。

### 2.3 输出纪律（机检报告写作规范）

1. **结论只写"机检结构匹配/不匹配"**——禁写"能过稿""会爆"；机检全绿 ≠ 能过稿（效果边界，见 `SKILL.md` 铁律 5）；
2. **关键词匹配必须输出命中词/位置/窗口/上下文**（可复算）；
3. **红线只提示待核**——不判死、不替平台表态；
4. **评分项可复算**——每项得分给出实测值 vs 门值；
5. **B1-B12 弱代理（情绪外化不足/工具人嫌疑/反转无铺垫/伪打脸等）只进"待人工复核清单"，不计分、不改 MSS**；
6. 密度代理双口径：工具口径（300/600/2000 字窗）与技能钩子口径（AT-27 系）**并行不互算、报告双写**。

## 三、主观六维评分（机检之后）

各 10 分：钩子密度 / 情绪浓度 / 人设统一（**对话符合身份带潜台词**）/ 逻辑自洽 / 合规性 / 结局爽透。

- **均分 ≥7 可投**；6-6.9 小修后复审；<6 不投（AT-61）；任一红线一票否决；
- **双裁决取严**：分数门与 S 级门（无 S1/S2）同时满足才可投。

**审稿动作链**：跑 `check-artifacts.py <项目目录>`（❌字段空缺先回补，⚠️对账差异随报告附上）→ 逐维打分 → 按 Findings Schema（S1-S4）输出问题清单 → 跑**逻辑验证八查**（因果链/信息差三层/规则边界/时间数字台账/行为合理性/反转公平/伏笔出处/人设事实核对）→ 过三级拒稿门（P0 格式 12 项 / P1 内容 47 项 / P2 商业 16 项 = 75 项，AT-54；**逐项勾选表见 `quality-gate.md` 第三节**）→ 给**四档结论**（可用/需补信息/需小修/需重写）。

## 四、根因路由（机检失分与六维失分回退到所属阶段）

| 失分面 | 回退阶段 | 修什么 |
|---|---|---|
| F 模块（字数/分节/段落/对话符号/句长） | 阶段 4 写作 | 形式合规：补删字数、统一分节、拆长段、「」对话 |
| B 模块（标题/导语/梗概/金句） | 阶段 2/3 | 标题三档（AT-24）、导语 80-150、梗概 ≤50 字含冲突词、金句 3-5 句 |
| T 模块（卡点/黄金三章/章末钩/开篇共现） | 阶段 3 细纲 | 付费点双卡重定位、黄金三章要素位补位、节末钩类型轮换 |
| D 模块（密度代理五项） | 阶段 4 写作 | 情绪锚点外化、推进/反转词密度、打脸兑现、新名词注入、钩子轮换 |
| R 模块（伏笔回收/核心词兑现） | 阶段 3/4 | 伏笔表补回收、核心词前 3000 字预埋（细纲标注承诺词） |
| 人设/情绪/逻辑主观问题 | 按所属阶段 | 人设卡/情绪弧线/逻辑链回对应阶段产物修 |

**每级回退最多 2 轮**（AT-51），两轮仍不过：停下如实汇报卡点与候选处置，交用户裁决，禁止无上限震荡。

## 五、终审工序（6b，按序执行，任一不过即回退）

1. **跨章扫描**：三查必做——①伏笔断裂/人设漂移/注释混入正文；②**道具转手链**（每件关键物件从出场到收尾的每一次易手都要有落点：谁给的、谁拿走的、谁最后拿着，缺一环就是断链）；③**时间表述差值**（同一事件的相对时间词「上个月/半年前/上一回」跨章须自洽，数字化的时间点须能对上）。三查任一断裂即回阶段 4 补写，不得只在报告里登记；
2. **跳读测试**：只读每章首尾+卡点，看钩子链是否成立；
3. **付费测试**：模拟读者三档自测（免费区读完想不想付费/卡点后是否必须知道答案/终局是否值回票价）；
4. **盲测对比（强制）**：与对照源混读三段，判"哪个更想往下读"；内部标准样例 = `tests/golden/` 文风样例 g10/g12/g14（作者手写、过机检片段口径），外部真爆款 = 可选增强。**盲测结论的边界必须写明**：A 组胜只证明"比内部标准样例更抓人"，**不证明能打赢当期榜上真作品**——没有外部真爆款对照时，报告须标注"⚠️ 未与外部真作品对照"，不得把内部对照的胜利表述为"具备爆款相"；
5. **18 维终审评分**：≥8.00 且无单项 <6 才可发（未隔离 ≥8.8，AT-62；评分表与打分纪律见 `quality-gate.md` 第二节）；**完读率代理三环必查（AT-77，多源印证）**：①开环·首锁前三连击（AT-18）②中环·中卡点 45-55%（AT-10）③闭环·**结尾前 500 字禁总结词收束**（末段落具体动作/画面/留白）——三环任一失守即回阶段 5 修结尾，机检 B6（最后 200 字弱代理）与 500 字主观口径分层不互替；
6. **红队终审**：切"拒稿编辑"身份，必须列出至少 3 条最想拒的点，禁止"未找到"一句带过；
7. **工序留痕核（check-process.py，交付硬前置）**：跑 `check-process.py <项目目录>`——工序表编号连续 / 结论项数与裁决表行数一致 / MSS 分值可追溯到机检数字报告节。**手抄进报告的数字最容易与稿件脱节**（改稿后重跑机检而报告未更新），此项机器秒查、人眼难辨，故设为打包前硬前置。

> **工序沿革**：原终审九工序中的「平台口径核验（条件项）」与「相似度检测（条件项）」两项已删除——平台规则以当期公示为唯一准源、投稿面按 `stage7-delivery/` 条件项口径交付，不再由终审设联网核验工序；抄袭/相似度红线（AT-23）的知识与红线判定保留在红线体系，不作为终审机检工序。删项后终审工序为七道，编号连续重排。

**工序留痕**：以上七道工序逐条登记进 `05-终审报告.md` 的「终审工序执行记录」表（工序号/结论/证据位）；任一项不过即按根因路由回退，禁跳项、禁事后补登。终审全过才进阶段 7 投稿打包。

## 六、产物

**产物（初审与终审各一份，双报告制）**：

- **`05-初审报告.md`**（固定四节：结论 / 最致命 3 问题 / Findings 全单 / 最小改动修改方案；**机检数字报告（MSS 五模块+12 硬门+待人工复核清单）作为第一节附件**）；
- **`05-终审报告.md`**（终审放行结论 + **终审工序执行记录表（七道工序逐条留痕，check-process 核验对象）** + 放行/回退结论）。

**随两份报告附两表**（6a/6b 的评分与拒稿门执行载体，缺一即门不过）：**18 维评分表**（模板见 `quality-gate.md` 第二节）与 **75 项勾选表**（模板见 `quality-gate.md` 第三节）。两表是审稿动作链的可复算留痕——评分每一维须能追溯到口径来源，勾选表每一项须有 ✅/❌/⚠️ 实判，禁只写"全过"二字。报告模板见 `../../templates/05-first-review.md`、`../../templates/05-final-review.md`。
