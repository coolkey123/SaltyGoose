# 阶段 7 · 交付 — rules（必须遵守什么）

> **本文件回答：有哪些约束、必须遵守什么。** 本阶段特有规范与禁令在此；全库通用红线见 `../../assets/compliance-redlines.md`（唯一正本）；术语口径见 `../shared/authority-table.md`。

> **R 编号命名空间**：本文件的 R1~Rn 只在本阶段内有效——其他阶段的 R 编号是各自 rules.md 的独立序列（如 R12 在阶段 5 指净稿冻结、在阶段 6 指待核项禁假合格）。**跨文件引用 R 编号必须带阶段名**（写「stage6 R12」或「阶段 6 规则 R12」），裸写「R12」视为无锚引用。

## 一、范围边界纪律（最高优先级）

| # | 规则 | 说明 |
|---|---|---|
| R1 | **本技能只到「创作 + 投稿打包」为止**——投稿发表后的阅读/订阅/点赞等运营数据一律**不跟进、不记录、不归因** | 范围越界即结构指纹与复盘台账混入运营指标，污染下篇选题的防同质化判断 |
| R2 | 禁以运营数据（曝光/读完率/收藏等）反推修改已交付作品或改写规则 | 技能迭代只走复盘三问与固化触发线，不走运营归因 |

## 二、投稿包禁令

| # | 禁令 | 说明 |
|---|---|---|
| R3 | **过程产物不入包**——梗概/细纲/标注稿/审稿报告等留项目目录备查；投稿包只含正文 + 后台投稿信息两件 | 过程产物入包 = 把创作痕迹交上去 |
| R4 | **投稿正文禁出现任何机检标记**——`[[首锁]]`/`[[二锁]]` 与方括号标注只存在于送机检提交包 | 标记混入投稿正文 = 直接把读者当机器 |
| R5 | **正文格式只收 docx/md**——禁 PDF、禁网盘链接 | 格式拒收是零成本可避的损失 |
| R6 | **标称即实测**——docx 命名字数引用 `check-length.py` 对**净稿 md** 的实测值（脚本只收 .md；docx 由净稿导出，命名引 md 实测值——禁对 docx 重新估算、禁手数字数） | 命名差 >10% 即改 |
| R7 | **禁平铺名词章题**——投稿章题必须带情绪动词（「我签了放弃继承声明」式） | 名词章题在后台列表里没有点击动机 |
| R8 | **禁自行断言平台规则**——当期公示检索不到时按缺省形态交付并备注"⚠️ 平台当期规则未核（无公开来源）"，禁把无来源的"当期规则"当改稿依据 | 平台规则以当期公示为唯一准源 |

## 三、复盘与固化禁令

| # | 规则 | 说明 |
|---|---|---|
| R9 | **复盘三问禁空答**——每篇必须找出最接近被拒的三个点；写"无问题"即打回重写 | 找不出三个点 = 阶段 6 审稿没做完 |
| R10 | **新篇选题先查指纹台账**——两篇指纹 ≥2 维同值 = 同型（AT-48），连续 3 篇同模式触红线（AT-46）回阶段 1 换模式重出 | 防同质化靠台账，不靠记忆 |

**复盘绑定（与 `SKILL.md` 收尾复盘段同文；两处任改其一即被 check-consistency 跨文件同文断言抓获）**：

**收尾复盘**：复盘三问（①最接近被拒的三个点 ②规则库里哪条救了/漏了它 ③要改技能文件的具体项）；**复盘完成后把未闭环问题摘要与结构指纹写入持久记忆**；**同一类问题连续 3 篇出现 → 必须改技能文件，禁止每篇人肉兜底**；**切片口径边界**：本阶段产物（投稿包/复盘/指纹）为**整篇级交付物，不标"适用范围：片段"**；仅当以片段/单步形态产出（如切片试读段）时，按切片产出两件套（AT-57 文首标签 + AT-76 文末口径备注）随片归档，缺一即格式门不过。

## 四、结构纪律

| # | 规则 | 说明 |
|---|---|---|
| R11 | **工序只许 A/B 两号**——投稿打包（A）/ 复盘登记（B）；终审类工序已整体并入阶段 6 收口，禁回流本阶段另起入口 | 终审回流 = 双入口双口径 |
| R12 | 本阶段只做投稿呈现层适配（节→章合并/命名/分隔符）——**不改创作期章结构**，不影响 check-length 章门与机检字位口径 | 交付层改结构 = 前面七阶段白干 |
