## 一、投稿包门（工序 A 出口，逐项过）

| # | 门条件 | 口径 |
|---|---|---|
| 1 | **投稿包只含两件** | 正文 + 后台投稿信息；过程产物（梗概/细纲/标注稿/审稿报告）不入包——`check-artifacts.py` R 项机检多出文件（样例 README 属说明文件已豁免，补） |

| 3 | **付费墙分隔符在位** | `——以下为付费章节——` 插在免费试读段与付费段之间；付费段起始句触发首次反转；投稿正文不出现 `[[首锁]]` 标记 |
| 4 | **docx 命名含标题+实测字数** | 《重生后我撕了婚书_12800字》形态；字数引 `check-length.py` 实测值（标称即实测） |
| 5 | **后台七字段齐全** | 作品名字/类型/标签/主角名字/主角人设/作品金句/内容简介——**七字段全部由 `check-artifacts.py` R 项机检**（从 4 项扩到全量七字段：名字 ≤20 字禁问号叹号 AT-24、标签 3-5 个、金句 1-2 句 ×15-25 字、简介 100-150 字、类型/主角名/人设非空）；短标题备选为可选字段（见门 8） |
| 6 | **作品名字合规** | ≤20 字不剧透、禁问号感叹号（AT-24）；标签 3-5 个；金句 1-2 句×15-25 字；简介 100-150 字（四项阈值均由 `check-artifacts.py` R 项机检，投稿面此前纯人工，超带要到编辑打回才知道） |
| 7 | **节→章对齐已处置** | 投稿期章节一一对应创作期章节；平台章数少于本篇时相邻章合并、章题带情绪动词，禁平铺名词章题 |

| 9 | **条件项状态显式** | 投稿面平台当期规则未核项在投稿包备注"⚠️ + 原因"，禁留空、禁假合格（投稿面条件项口径；原引用阶段 6 终审条件项指针随删项已废止） |
| 10 | **送机检提交包四件齐** | 正文纯文本（净稿+双锁标记）/标题导语梗概/金句列表/伏笔回收 CSV，与投稿包分立；`check-artifacts.py` M 项机检（四件齐 + `[[首锁]]` 标记 + CSV 五字段），目录不存在 = 未到送检时点 |

## 二、复盘门（工序 B 出口，逐项过）

| # | 门条件 | 口径 |
|---|---|---|
| 1 | **复盘三问齐答** | ①最接近被拒的三个点 ②规则库哪条救了/漏了它 ③要改技能文件的具体项 |
| 2 | **结构指纹登记** | 六维指纹追加进台账；**实落回填后跑 `check-fingerprint.py` 比对**（exit 0 或 exit 2 预警已处置——shared/fingerprint.md 明定"阶段 7/复盘"为调用时点，此前本阶段三文件零落点）；新篇选题先查台账防同质化（两篇 ≥2 维同值 = 同型，AT-48） |
| 3 | **持久记忆绑定** | 复盘完成后把未闭环问题摘要与结构指纹写入持久记忆 |
| 4 | **固化触发线执行** | 同一类问题连续 3 篇出现 → 必须改技能文件，禁止每篇人肉兜底 |

## 三、确认门④

方式②：用户点头后才作为成品交付；方式①：打包完成即自动交付，用户可随时叫停回退。交付时提示用户跑收尾复盘。

## 四、不过的处置

| 门不过 | 处置 |
|---|---|
| 七字段缺项 | 回工序 A 补齐再交付——缺字段的后台提交直接被打回 |
| docx 命名字数与实测差 >10% | 重命名（标称即实测，禁估算字数） |
| 投稿正文残留 `[[首锁]]` | 换净稿重出——机检标记只存在于送机检提交包 |
| 章题为平铺名词 | 改为带情绪动词章题（「我签了放弃继承声明」式） |
| 复盘三问缺答 | 补齐再交付——复盘是固化触发线的数据源，缺项 = 下篇重复踩坑 |
| 过程产物混入投稿包 | 清出（过程产物留项目目录备查） |
